# Quickstart

## Basic consolidation

```bash
# 1. Run inside the package folder — the path defaults to "."
cd src/mypackage
pyrefactor
# -> src/mypackage/consolidated/mypackage.py

# 2. …or point at the package from anywhere
pyrefactor src/mypackage
# -> src/mypackage/consolidated/mypackage.py

# 3. …or choose another output directory
pyrefactor src/mypackage -o dist
# -> dist/mypackage.py
```

There is no ``-m``/``--mode`` flag any more: one call always produces one
file, ``<pkgname>.py``, inside a ``consolidated/`` subdirectory.

The generated file contains, in this order:

1. a module docstring,
2. ``__future__`` imports and the optimized import section
   (de-duplicated, relative/local imports stripped),
3. constants (``const.py``),
4. classes (``classes.py``),
5. functions (``func.py``),
6. entry points and ``if __name__ == "__main__":`` guards,
7. an ``__all__`` section generated by `autoall` in place.

The package name used for the file name is detected from
`pyproject.toml`/`setup.cfg`/`setup.py` in the package folder **and up to two
directory levels above it** (so ``src/<pkgname>`` layouts work). When nothing
is found, the name of the folder you pointed at is used. Names are normalised
to valid module names: ``my-dist`` → ``my_dist``.

## Dry-run & check (CI)

```bash
pyrefactor src/mypackage --dry-run          # report, write nothing
pyrefactor src/mypackage --check --diff     # exit 2 when the file would change
```

`--check` compares the generated file byte-for-byte (including the `__all__`
section) and prints a unified diff when it differs. It is idempotent: run it
twice after a successful build and it passes.

## Stdout & diff

```bash
pyrefactor src/mypackage --stdout > consolidated.py
pyrefactor src/mypackage --diff            # print the diff against the file
```

## Data files

```bash
pyrefactor src/mypackage --copy-data
pyrefactor src/mypackage --copy-data --data-glob "*.json"
```

Data files (`.json`, `.yaml`, `.csv`, `.txt`, `.ini`, `.toml`, …) are
discovered via `discovery.discover_data_files()` and copied next to the
generated module, preserving their path **relative to the package directory**
so `Path(__file__).parent / "data/…"` keeps working.

## Formatting & validation

```bash
pyrefactor src/mypackage --format --formatter black --validate
pyrefactor src/mypackage --validate-import
```

## Include / exclude

Precedence: `default excludes < --include < --exclude`

```bash
pyrefactor src/mypackage --exclude "tests/*" --include "conftest.py"
```

## Entry points

```bash
pyrefactor src/mypackage --entry mypackage.cli
pyrefactor src/mypackage --entry-keep-all
pyrefactor src/mypackage --main-name cli_main --generate-guard
```

## Namespaces & source maps (debugging)

```bash
pyrefactor src/mypackage --source-map --preserve-modules --namespace
```

Adds per-block:

```python
# Original module: pkg.sub.mod
# source: src/pkg/sub/mod.py:10-25
# namespace: pkg.sub.mod
def foo(): ...
```

## Configuration file

`pyproject.toml` next to (or above) the package is read automatically:

```toml
[tool.pyrefactor]
exclude = ["tests/*", "ignored.py"]
entry = ["mypackage.cli"]
rename_strategy = "suffix"
dedupe = "safe"
imports = "prune"
all = "respect"
format = true
```

```bash
pyrefactor src/mypackage                      # auto-detected
pyrefactor src/mypackage --config other.toml  # explicit file
pyrefactor src/mypackage --main-name run      # CLI flag wins over config
```

## Python API

```python
from pathlib import Path
from refactor_utils.core import consolidate_package

# Single consolidated file: src/mypackage/consolidated/mypackage.py
result = consolidate_package(Path("src/mypackage"), validate=True)
print(result.modules, result.exports, result.pkg_name, result.files)

# Custom output directory: dist/mypackage.py
result = consolidate_package(Path("src/mypackage"), Path("dist"))

# Everything the CLI does is available as a keyword argument
result = consolidate_package(
    Path("src/mypackage"),
    rename_strategy="suffix",
    entry=("cli",),
    main_name="run",
    copy_data=True,
    do_format=True,
    formatter="black",
    check=False,
)
```

The lower-level `refactor_utils.core.consolidate()` (multi-file `output/`
layouts driven by `mode="single"|"package"|"module"|"flat"|"split"`) is still
available for library users; the `pyrefactor` CLI always produces the
single-file consolidated layout.
